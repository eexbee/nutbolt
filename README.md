# Nutbolt

Nutbolt - production Linux server hardening framework: interactive
single-server deployment, multi-server Ansible deployment, automatic
discovery, YAML configuration, security auditing and rollback.

## Supported operating systems

| OS | Package manager | Firewall |
|---|---|---|
| Ubuntu 22.04 / 24.04 LTS+ | apt | UFW |
| AlmaLinux 9+ | dnf | firewalld |
| Rocky Linux 9+ | dnf | firewalld |

## Quick start

```bash
# 1. Copy the nutbolt/ directory to the target server, then:
chmod +x *.sh lib/*.sh modules/*.sh modules/profiles/*.sh discovery/*.sh audit/*.sh

# 2. (optional) discover what is running on the server
sudo ./discover.sh                 # writes config/generated/server-auto.yml

# 3. harden (interactive)
sudo ./install.sh

# 3b. or config driven
sudo ./install.sh --config config/generated/server-auto.yml

# 4. audit
sudo ./audit.sh                    # writes reports/security-audit.txt

# 5. rollback if required
sudo ./rollback.sh                 # pick a backup, restores everything
```

## Workflow

```
Discover -> Generate configuration -> Review -> Harden -> Audit -> Report
                                                          \-> Rollback if required
```

## Commands

| Command | Purpose |
|---|---|
| `sudo ./install.sh` | Interactive hardening (user, SSH, firewall, fail2ban, ClamAV, updates, sysctl, limits, profiles) |
| `sudo ./discover.sh` | Detect hardware/services/ports and generate `config/generated/server-auto.yml` |
| `sudo ./audit.sh` | Weighted security score (0-100) + `reports/security-audit.txt` |
| `sudo ./rollback.sh` | Restore SSH/sysctl/limits/firewall from a backup snapshot |
| `./generate-ansible.sh` | Generate a complete Ansible project in `ansible/` |

### install.sh options

```
-c, --config FILE        merge a YAML config (highest priority)
-n, --non-interactive    never prompt (config must be complete)
-s, --skip LIST          skip modules, e.g. -s clamav,docker
    --only LIST          run only these modules, e.g. --only ssh,firewall
-v, --verbose            debug output
```

## Configuration

Base: `config/default.yml` — per server: `config/servers/<hostname>.yml`
(explicit: `--config FILE`). Profile selection:

```yaml
profiles:
  web:      { enabled: true }
  database: { enabled: true }
  redis:    { enabled: true }
  minio:    { enabled: false }
  docker:   { enabled: true }
```

## Profiles (combinable)

- **web** – TCP backlog, port range, file limits; nginx / Apache / OpenLiteSpeed aware
- **database** – nofile 100000 (mariadb/mysql/postgres), swappiness/dirty ratios; never restarts your DB
- **redis** – `vm.overcommit_memory=1`, `somaxconn=65535`, THP disabled
- **minio** – nofile 200000, storage-friendly kernel settings
- **docker** – `daemon.json` json-file log rotation + `live-restore`; networking untouched

## Security philosophy

1. Every change is backed up first (`backups/<timestamp>/`).
2. Root SSH is never disabled before a tested admin account exists.
3. `sshd -t` validates configuration before every SSH restart.
4. The old SSH port stays open until login on the new port is confirmed.
5. All actions are logged (`logs/`).
6. Tuning is conservative - nothing that breaks production workloads.

## Multi-server (Ansible)

```bash
./generate-ansible.sh
cd ansible
$EDITOR inventory.ini          # add servers to profile groups
ansible-galaxy collection install community.general ansible.posix
ansible-playbook -i inventory.ini site.yml
```

## Layout

```
install.sh rollback.sh discover.sh audit.sh generate-ansible.sh
config/         default.yml, servers/, generated/
lib/            logging, common, backup, os_detect, config_loader, validation
modules/        user ssh firewall fail2ban clamav updates sysctl limits services
modules/profiles/  web database redis minio docker
discovery/      hardware services network packages
audit/          checks scoring report
ansible/        (generated by generate-ansible.sh)
backups/ reports/ logs/
```

## Notes

- Developed on Windows? Run `dos2unix` on all files if you see `\r` errors on Linux:
  `find . -name '*.sh' -o -name '*.yml' | xargs dos2unix` (files ship with LF endings).
- ClamAV daily scans exclude database/Docker/MinIO directories by default.
- `security-scan /path` runs ClamAV with `nice`/`ionice` to protect production load.
